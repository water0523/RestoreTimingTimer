# timing 计时器（RestoreTimingTimer）

**v1.5.0**

单文件（`index.html`）的沉浸式学习计时器：设定时长 → 全屏背景 + 进度环 → 到点提醒 → 记录 / 导出。
所有可选项都在设置弹窗里（默认全开），云同步已在 v1.3.0 移除。
版本号也显示在设置弹窗底部（齿轮图标），单一来源是 `index.html` 里的 `APP_VERSION`。

在线地址：<https://water0523.github.io/RestoreTimingTimer/>

> 仓库设置里的主页字段目前还是改名前的 `https://water0523.github.io/timing-/`（已 404），
> 建议在 GitHub 仓库设置里改成上面这个地址。

## 本地使用（桌面浏览器）

直接双击 `index.html` 就能用，所有数据保存在浏览器 localStorage 里，不会自动上传。

也可以起个本地静态服务（更接近线上环境）：

```bash
python -m http.server 8000     # 然后打开 http://localhost:8000/
```

## 功能要点

- **保持屏幕常亮**（v1.2.9 起，默认开启）：只要人还停在计时器这个页面上，就不让屏幕休眠
  （用的是浏览器的 Screen Wake Lock 接口，计时中、暂停中都算）。切到别的标签页、最小化或锁屏时自动放开，
  回到本页面再自动接管。设置弹窗（⚙）里可以关掉这个设定；浏览器不支持时开关会置灰，不会假装生效。
- **标签页标题实时显示剩余时间**：`25:00 · 背单词`，暂停时变成 `已暂停 · 背单词`，切到别的标签页也能看到进度。
- **顶部毛玻璃当前时间**（v1.2.8 起）：开始计时后，鼠标一动就在屏幕正上方浮出一枚苹果风毛玻璃圆角药丸，
  显示当前时间（`HH:MM:SS`，精确到秒）；鼠标停下 3 秒后自动渐隐（0.4s 过渡），期间继续移动会重新计时。
  浮层是 `pointer-events: none`，永远不会挡住"结束 / 暂停"按钮；弹窗打开时一律不显示。
  秒级定时器只在浮层可见时挂，并且对齐真实整秒（不会越走越慢）。
- **记住上次设置**：任务名和学习时长会记下来，下次打开自动回填（时长只提示"已记住上次设置"，不写死结束时间）。
- **到点提醒**：总结弹窗 + 标签页标题闪烁 `⏰ 时间到！`。**本应用不播放任何声音**，没有音效代码。
- **历史记录合计**：列表顶部吸顶显示"共 N 条 · 今日 X · 本周 X"与"累计 X"。今日、本周、热力图与连续天数统一按专注开始日期归属，跨午夜保存或暂存后隔天继续也不算到保存当天。
- **历史记录可改名**：在历史里点一下任务名就能改（`Enter` 保存 / `Esc` 取消 / 点别处保存），
  只改标题，时长、开始时间和备注都不动。
- **专注热力图**：历史记录里有一张类似 GitHub 贡献图的热力图（最近 18 周，列 = 周、行 = 星期）：
  灰 = 当天没用过，蓝 = 用过，紫 = 当天超过 4 小时，红 = **当天达到 8 小时**（单次时长上限就是 8 小时，
  所以红是"满 8 小时"而不是"超 8 小时"；一天里多段累加也算）；
  点任意圆点会在下方显示那天的日期、记录条数和当天总时长；顶部有颜色图例和 `?` 说明。
- **连续使用天数**：热力图右上角显示连续使用的倍数徽章 `×N`（第 1 天用浅色"连续 1 天"提示）。
  今天还没开始不算断，会从昨天继续往前数；断掉后徽章消失。
- **任务建议**：用过的任务都会进建议（按使用次数排序，最多 8 条），输入时按内容模糊筛选（输入"背词"也能命中"背单词"）。
- **暂存 / 续上一次**：一场专注结束时，弹窗里除了"保存记录 / 不保存"还有"暂存"——
  把已用时长和任务名存下来（**不写记录**），回到主页会出现提示条「上次的『背单词』还剩 18 分 30 秒」，
  点"继续"接着跑，点"丢弃"清掉。暂存期间的时间不算进专注时长；续上之后再结束，
  记录里的开始时间仍然是原来那次的时间。
  （同一时间只保留一份暂存，再次暂存会覆盖；暂存内容存在浏览器本地。）
- **自动恢复（防刷新 / 崩溃）**：计时进行中每 5 秒把进度写进浏览器本地，切到后台、关闭页面前也会各补一次；
  刷新页面、误关标签页、浏览器崩溃后回到主页，提示条会写「上次没结束的『背单词』还剩 12 分 10 秒」，
  点"继续"接着跑，最多只丢几秒。手动"暂存"和自动快照可以同时存在，提示条显示较新的那一份。
- **进度环按 20 分钟一圈**，每圈自动切换一张背景图；切到后台再回来会按真实进度对齐图片。
  切图节点除了帧循环还有 `setTimeout` 兜底，窗口被遮挡/切后台导致 rAF 被节流时也不会漏；
  需要的话按 `右 Ctrl + →` 可以手动强制切下一张。
- **背景图加载策略**（v1.2.6 起）：
  - 计时中在**下一个 20 分钟节点到来前 90 秒预取"下一张"**——到点切图零等待，开场也不会一下吃 7.4MB；
  - 回到主页空闲时再把 24 张慢慢预热；一进计时或开发者模式就让路，不抢带宽；
  - 线上用 **Service Worker** 把背景图永久缓存在本地（GitHub Pages 只给 `max-age=600`，10 分钟就过期，
    而计时器 20 分钟才切一次图）——首次访问之后**断网也能正常切图**，开发者模式来回跳也是秒切。
- **暂停是真的暂停**：计时、进度环、文字呼吸、背景平移与三圈波纹动画全部冻结。
  文字呼吸的相位由"已用时长"推导（`(已用时长 - 10s) % 20s`），所以暂停再恢复不会和 20 秒节奏错位，
  恢复时也不会重播开场翻转动画；暂停期间不会再去加载新的背景图。
- **背景平移与文字呼吸严格对齐**（v1.4.2 起）：背景的左右平移不再是 CSS 关键帧动画
  （那种动画从"元素渲染那一刻"按墙钟跑，刷新页面 / 切后台再回来 / 暂停恢复之后就和时间轴对不上），
  而是每帧和文字呼吸一样按"已用时长"算出来。节奏：单程 20 秒、一去一回 40 秒，
  **起点（已用 0 秒）在最右边**，折返只发生在 20 秒的整数倍上：
  0s = 最右（开始向左）→ 20s = 最左（折返）→ 40s = 最右（一个完整循环，再次折返）。
  文字每 10 秒切换一次，所以每次折返、每次走到一半，都恰好压在文字切换的那一刻；
  20 分钟换图时"已用时长"必然是 40 秒的整数倍，每张新图都从"最右 + 整循环起点"开始。

## 快捷键

| 按键 | 作用 |
| --- | --- |
| `空格` | 暂停 / 继续（计时页） |
| `右 Ctrl + →` | 强制切到下一张背景图（不影响 20 分钟基准，下一个节点照常再切一张） |
| `Esc` | 关闭最上层弹窗（总结弹窗按 Esc 视为"不保存"） |
| `Shift + Enter` | 进入 / 退出全屏 |
| 页面空白处三连击 | 进入全屏 |
| 任务名输入框里输入 `water` 再回车 | 开发者模式（8 小时时间轴，调试用；计时页显示当前时期名） |

计时进行中刷新或关闭页面会弹确认框，避免误操作丢掉整段专注时间。

## 目录说明

- `index.html`：整个应用（HTML + CSS + JS 单文件）
- `images/*.webp`：24 张背景图，每 20 分钟自动切换一张

| 计时与提醒 | 到点时闪烁标签页标题 | 时间到只弹总结弹窗，标题不闪 |

### 固定位置的备份文件（数据备份）

在设置里点「选择 / 更改备份文件」选一个 `.json`（建议放到网盘的同步文件夹里），浏览器会记住这个文件；
之后**每次保存记录都会把新数据合并写进这同一个文件**，不会再生成一堆带时间戳的副本：

- **覆盖合并**：同一个 `id` 只保留一条；本机改过任务名以本机为准；文件里本机没有的记录会被保留下来
  （所以两台设备先后各写一次，文件里两份记录都在）。
- **删除同步与撤销**：删除标记保留在本机和备份中，即使删除时未获授权或写入失败，下次备份也不会带回旧记录。在历史窗口点「撤销最近删除」可逐条恢复本页删除的记录；刷新后撤销入口清空，删除标记仍保留。
- **安全写入**：同一页面的写入依次排队，浏览器支持时跨标签页也协调执行；备份文件读取失败、损坏或格式不正确时停止写入，保留原文件。
- 想换位置点「更改文件」；「断开」只是不再写这个文件，本机记录不会被动。
- 前提：网页没有权限直接往任意磁盘路径写文件，所以必须由你**选一次**文件（Chrome / Edge 支持，
  本地双击 `index.html` 也能用）。浏览器不支持时会提示改用历史记录里的「导出备份」（下载一份
  `timing-backup.json`）。选过之后浏览器可能偶尔要求重新授权，点一下「立即写入一次」即可。

> **云同步已在 v1.3.0 整体移除**（GitHub Token、仓库配置、`data/records.json` 读写全部删掉）。
> 老版本存在浏览器里的 Token 会在升级后第一次打开页面时被自动清除。
> 跨设备搬记录请用历史记录弹窗里的「📤 导出备份 / 📥 导入备份」，或者上面这个固定备份文件。

## 导入预览、合并与删除撤销

历史窗口点击「导入备份」选中 JSON 后，先显示预览，确认前不会改动本机记录：

- 默认「合并」，保留本机已有记录并补充备份中的新记录；按 ID 去重。
- 预览显示新增、重复、冲突数量、最终记录数和删除标记影响，列出前 30 条明细；确认时处理全部记录。
- 同 ID 内容不同默认保留本机内容，也可选择采用备份内容。
- 保留「覆盖」方式：替换本机记录，确认时再次提示；已有删除标记仍然有效。
- 逐条验证记录、任务建议计数和删除状态；无效文件整体拒绝，避免写坏本机数据。存储写入失败会尝试恢复此前已写入的本地键。
- 在历史窗口点「撤销最近删除」可按最近删除顺序逐条恢复，任务名、原开始时间、时长、备注和 ID 都保留，备份中的删除状态也随之更新。

### 按开始日期统计旧记录

新记录保存标准开始时间戳，原来的开始时间显示文字仍保留。旧记录通过原 `startTime` 解析开始日期，支持中文年/月/日、上午/下午和常见英文时间格式，因此昨天专注、今天保存的旧记录也会归到昨天。

无法识别开始日期的旧记录不猜测日期：保留记录与累计时长，统计栏提示数量，不纳入今日、本周、热力图及连续天数。整段专注归属开始日期，不在午夜拆分。

- 计时过程中刷新页面的情况已被"自动恢复"覆盖：最多丢 5 秒，回主页点"继续"即可接着跑。

### v1.4.2（已发布到 GitHub Pages）

- 修复：**背景平移和文字呼吸对不齐**（刷新页面 / 切到后台再回来 / 暂停恢复之后特别明显）。
  原因：文字呼吸的相位是**按"已用时长"算**的（所以它总能对上），
  而背景平移是一句 CSS 关键帧动画（`animation: moveBg 20s linear infinite alternate`）——
  它从"元素第一次渲染"开始按墙钟自己跑，和"已用时长"没有任何关系，两者各走各的。
- 改法：去掉那句 CSS 动画，改成每帧用 `syncBackgroundPan()` 按"已用时长"算位置，
  和文字呼吸共用同一条时间轴。节奏不变（单程 20 秒、一去一回 40 秒），
  **起点（已用 0 秒）在最右边**，折返只发生在 20 秒的整数倍上：
  | 已用时长 | 文字 | 图片位置 |
  | --- | --- | --- |
  | 0s | 显示（开场） | **100% 最右**，从这里开始向左走 |
  | 10s | 隐藏 | 50%（走到一半） |
  | 20s | 显示 | **0% 最左，方向在这里折返** |
  | 30s | 隐藏 | 50% |
  | 40s | 显示 | **100% 最右，一个完整循环，再次折返** |
  于是每 40 秒正好一个完整循环，折返只出现在 20 秒的整数倍（0/20/40/60…），
  不会出现"十位是奇数时折返"这种怪现象；而文字每 10 秒切换一次，
  所以每次折返、每次走到一半，都恰好压在文字切换的那一刻。
  另外每 20 分钟换图时"已用时长"是 20 分钟的整数倍，必然也是 40 秒的整数倍，
  所以每张新图都从"最右 + 一个完整循环的起点"开始，永远整齐。
  实测（真实 DOM 采样）：已用 0/20/40/60 秒时图片在 99.7% / 0.25% / 99.7% / 0.25%，
  10/30/50 秒时在 50% 附近，与理论值一致。

### v1.4.1（已发布到 GitHub Pages）

- 修复：**每 20 分钟自动切图的那一瞬间，背景会"闪一下"**。
  原因：原来只有一层背景，直接把 `background-image` 换掉；这些图都是 2560px 的大图，
  浏览器要现场解码，解码的那一帧背景是空的（黑一下），看起来就是闪。
  现在改成**两层背景轮换**：新图先铺在下面那一层，**等 `img.decode()` 解码完成**再淡入，
  旧图同时淡出（0.8s 交叉淡化）。实测切换过程中两层不透明度之和恒为 0.80，
  也就是全程屏幕上都有完整背景，不再有空帧。
  （顺带发现：原来那句 `transition: background-image 1s` 是死代码——Chrome 并不对
   `background-image` 做补间，实测直接就是硬切，所以以前也没有真正的淡入淡出。）
- 修复：**切图那一瞬间会先冒出"上一个阶段"的文字，再跳到新阶段**。
  原因有两个，叠在一起：
  1. 隐藏旧文字用的是 CSS 里 1.5s 的透明度过渡，而 1 秒后就把内容换成新的了 ——
     新旧文字会有一段时间重叠/先后出现。现在换字时临时关掉过渡，让旧文字**瞬间消失**。
  2. 更要命的是：rAF 每帧都会调 `syncBreathing()`，相位一算到"该显示"，
     就把刚藏起来的**旧时期名**重新放了出来。现在换字期间会短暂屏蔽相位干预（`STAGE_SWITCH_MS = 400ms`），
     等新内容写进去之后再交回给相位决定显示还是隐藏（同一次 tick 内完成，不会闪一帧）。
  最终效果：切换瞬间旧文字立刻消失 → 400ms 后新阶段文字淡入。
