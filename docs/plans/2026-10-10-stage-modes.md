# Stage Mode Switch Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 设置中保留原版 24 阶段模式，默认使用用户确认的 36 阶段模式；本地完成并验证。

**Architecture:** 保留完整 36 阶段资源，原版模式按图片 1–24 顺序引用同一份标题和文案。偏好记录下一次专注的模式，活动会话保留自己的模式；暂存与自动快照包含模式信息，恢复不截断长会话。图片内存缓存改用图片路径作为键，避免不同模式中同一数字下标对应不同图片。

**Tech Stack:** 原生 HTML/CSS/JavaScript、Node 内置回归测试、Playwright 本地浏览器检查。

---

## 已确定的行为

- 设置 → 通用 → 阶段模式：默认「36 阶段 · 12 小时」，可选择「原版 24 阶段 · 8 小时」。每阶段继续保持 20 分钟。
- 空闲时立即切换时长滚轮、时长上限、开发者时间轴、预加载数量。已选时长超过新模式上限时显示新上限。
- 运行、暂停或总结期间仅更新下一次专注偏好，当前图片、时间、目标与记录不变；设置说明提示生效时间。
- 恢复显式保存的会话模式。旧 v1.6.0 暂存没有模式字段时沿用此前的 36 阶段行为，避免把短于 8 小时的 36 阶段会话误判为原版。
- 切换时取消旧模式的预加载与延迟跳转，丢弃过期切图回调。图片缓存仍保留 6 张上限，按路径复用，重试捕获原图片路径。

## Task 1: 验证模式与会话行为

**Files:** Modify `tests/regression.test.cjs`.

1. 增加偏好初始化支持；测试默认 36、原版全部 24 阶段顺序、保存与刷新、8/12 小时滚轮与开发者轴。
2. 测试运行与暂停中切换不改变本次会话，保存会话模式，恢复两种模式及旧无标识快照。
3. 测试图片缓存和延迟解码/失败重试不会串图。
4. 执行 `node --test tests/regression.test.cjs`，确认新测试先失败。

## Task 2: 实现选择与资源切换

**Files:** Modify `index.html`.

1. 在通用设置中添加匹配现有样式的下拉选择及生效说明，保存受校验的 `stageMode` 偏好。
2. 引入活动模式、按当前资源数计算的时长上限，单独重绘小时选项以免重复绑定事件。
3. 在开始、回到主页和恢复时应用相应模式；快照记录活动模式。
4. 缓存按图片路径索引，切换时停止旧预加载与延迟跳转，并使旧切图回调失效。
5. 下拉选择聚焦时不触发暂停和全屏快捷键；预加载说明随模式更新。

## Task 3: 文档与浏览器检查

1. 更新当前版本至 v1.6.1，说明默认模式、原版模式、切换生效时机与恢复策略，保留历史版本日志。
2. 执行所有回归测试，并在浏览器验证设置选择、刷新保留、两种时间轴的首尾与全部图片、待生效切换和跨模式恢复。
3. 检查差异，同步本地 C 盘工作副本与 D 盘项目并打开预览；不推送。
